# Where KompozR's showcase differs from the C++ Kompoz showcase, and why (showcase::shots, `showcase-shots compare`).
# A line: `config part x y width height causes…` (dp in the part: `top` the top app bar, `bottom` the navigation bar,
# `s00`…`s26` the Material tab's sections in order), or `config part height causes…` where the part's height
# differs. Written by tools/stage12-notes/wp9/regions.py from a comparison after the review below; every cause was
# looked at section by section (WP9's report), the text causes measured by a run with C++'s text rules.
#
# The causes:
# T-SPACE   Letter spacing in whole pixels: KompozR sets text as Compose on Android (minikin's LayoutCore rounds a
#           non-linear text's letter spacing to whole px: 0.2 sp at density 1 is none), the C++ showcase adds it
#           fractionally. Shifts every glyph after the first, so the widths of chips, buttons and tabs too.
# T-TRACK   M15's type scale tracking (bodyMedium and titleMedium 0.2 sp, displayLarge -0.2 sp) against the C++
#           showcase's M3 1.0 values (0.25, 0.15, -0.25).
# T-PAD     A line whose font reaches beyond its line height (Noto Sans 12 sp spans 16.34 px in a 16 sp line) is
#           padded as Compose's TextLayout pads it (LineHeightStyleSpan's first ascent / last descent), the C++
#           showcase lets it overflow: text fields 1 px taller, sections a px or two taller.
# T-GLYPH   Glyphs at other subpixel positions where the advances add up differently (the C++ showcase's HarfBuzz
#           26.6 advances, KompozR's harfrust float ones): the same glyph rasterized at another fraction.
# T-DIR     Text direction: Compose resolves an unspecified one to the layout's (Ltr), so the Arabic second
#           paragraph of the notes field is laid out left to right; the C++ showcase resolves each paragraph by its
#           first strong character.
# SLIDER    Compose's Slider and RangeSlider draw Material 3's bar thumb and thick track by default; the C++
#           showcase's default is its classic circle and thin track (the thumb chooser's "Daire" matches it).
# ICONBTN   A Button with an icon written as Compose's samples do (ButtonWithIconContentPadding, 16 dp start, and
#           IconSpacing); the C++ Button spaces its content 8 dp apart inside its 24 dp padding.
# BUTTONGROUP The overflowing ButtonGroup isn't fillMaxWidth: M15 measures its overflow indicator at most as wide as
#           the room left, which a fixed width's minimum exceeds (Constraints.copy throws there in Compose too).
# SHORTNAV  M15's ShortNavigationBarItem puts its icon on top unless given iconPosition = Start; the C++ one puts it
#           at the start in a centered bar.
# SHADOW    Elevation shadows depend on where in the window they are (the light above the window's middle): the
#           section was shot at another scroll position (the sections above it differ in height).
# ANIM      An infinite animation's phase (the preferred frame rate dot) at the frame the section was shot.
# M15-…     Material 3 1.5 (M15, alpha17), which KompozR follows for every component, against the C++ showcase's
#           1.4-era values: -BUTTON (Expressive sizes and paddings, OutlinedButton's label in onSurfaceVariant,
#           disabled colors), -CHIP, -FIELD (text field paddings and labels), -SEARCH (the input field's paddings,
#           the leading icon in onSurface), -SWITCH (the thumb), -SEGMENTED, -CHECKBOX, -TABS, -LIST, -FABMENU (the
#           toggle FAB inside the menu's padding), -RAIL (the wide rail's header), -TOOLBAR (the vertical toolbar's
#           FAB at its end, its size).
